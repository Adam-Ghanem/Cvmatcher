# CVMatcher API

## Versioning and conventions

Phase 1 API routes are versioned beneath `/api/v1`. API responses use JSON. A request correlation identifier is accepted through a valid UUID `X-Request-ID` header or generated by the server, then returned in the response header.

Errors use this envelope:

```json
{
  "error": {
    "code": "DEPENDENCY_UNAVAILABLE",
    "message": "The service is not ready. Please try again shortly.",
    "requestId": "3f79e747-17ab-4c80-9e5a-4a9e438471f8"
  }
}
```

The error message is safe for customers. It does not include exception messages, database URLs, parser diagnostics, storage keys, prompts, or credentials.

## Implemented endpoints

| Method | Path | Response | Purpose |
|---|---|---|---|
| `GET` | `/api/v1/health` | `200 {"status":"ok"}` | Process health. Does not require PostgreSQL. |
| `GET` | `/api/v1/ready` | `200 {"status":"ready","database":"ready"}` or `503` error envelope | Dependency readiness. Performs `SELECT 1` against PostgreSQL. |

## Phase 1 exclusions

There are no endpoints for accounts, sessions, CV uploads, document downloads, job descriptions, analyses, matching, OpenAI, recommendations, billing, or data deletion yet. These endpoints must not be added without Pydantic input/output contracts, authenticated principal resolution, ownership enforcement, error tests, and rate-limit considerations.
